## Authentication

Most endpoints (cases, watchlist, alerts) expect a Bearer token in the `Authorization` header, obtained from `/api/auth/login` or `/api/auth/register`. The frontend stores this token in `localStorage` under the key `sentinel_token`.

```
Authorization: Bearer <token>
```

## Investigation

### `POST /api/investigate`

Runs a full OSINT investigation on a given identifier.

**Request body:**
```json
{
  "query": "google.com",
  "type": "domain"
}
```
`type` must be one of: `"email"`, `"username"`, `"domain"`, `"phone"`, `"wallet"`

**Response:** `InvestigationResponse` — see full field breakdown below.

```json
{
  "success": true,
  "query": "google.com",
  "type": "domain",
  "sources": [ /* array of ConnectorResult */ ],
  "profile": { /* consolidated attributes */ },
  "risk": { "score": 40, "level": "Medium", "reasons": [ /* ... */ ] },
  "correlation": {
    "entities": [ /* ... */ ],
    "relationships": [ /* ... */ ],
    "pivot_points": [ /* ... */ ]
  },
  "graph": { "nodes": [ /* ... */ ], "edges": [ /* ... */ ] },
  "timeline": [ /* array of TimelineEvent, newest first */ ],
  "image_correlation": { /* ... */ },
  "synthetic_identity": { /* ... */ },
  "related_cases": [ /* ... */ ],
  "summary": {
    "risk_level": "Unknown",
    "summary": "...",
    "key_findings": [ /* ... */ ],
    "recommendations": [ /* ... */ ]
  },
  "message": null
}
```

**`ConnectorResult` shape** (each entry in `sources`):
```json
{
  "source": "RDAP",
  "success": true,
  "data": { /* connector-specific fields, or null on failure */ },
  "error": null
}
```

**`TimelineEvent` shape** (each entry in `timeline`):
```json
{
  "date": "2028-09-14 04:00:00 UTC",
  "date_sort": "2028-09-14T04:00:00+00:00",
  "title": "Domain Expiration",
  "description": "google.com domain registration expires",
  "source": "WHOIS",
  "type": "domain_registration",
  "url": null
}
```

## Case Management

### `POST /api/cases`
Save an investigation result.
```json
{
  "query": "google.com",
  "type": "domain",
  "result": { /* full investigation response */ },
  "tags": ["priority"],
  "notes": "Flagged for follow-up"
}
```

### `GET /api/cases`
List saved cases. Optional query param: `?tag=priority`

### `GET /api/cases/{caseId}`
Retrieve a single saved case by ID.

### `PATCH /api/cases/{caseId}/notes`
```json
{ "notes": "Updated notes" }
```

### `PATCH /api/cases/{caseId}/tags`
```json
{ "tags": ["priority", "reviewed"] }
```

### `DELETE /api/cases/{caseId}`
Delete a saved case.

### `GET /api/cases/{caseId}/export.json` / `export.csv`
Download a saved case in the given format.

## Watchlist & Alerts

### `POST /api/watchlist`
```json
{
  "query": "example.com",
  "type": "domain",
  "interval_hours": 24,
  "label": "Client monitoring"
}
```

### `GET /api/watchlist`
List active watchlist entries.

### `DELETE /api/watchlist/{watchId}`
Remove a watchlist entry.

### `GET /api/alerts?unacknowledged_only=false`
List generated alerts.

### `POST /api/alerts/{alertId}/acknowledge`
Mark an alert as acknowledged.

## Error Responses

Most endpoints return errors in this shape (non-2xx status):
```json
{ "detail": "Error message here" }
```

The `investigate` endpoint specifically degrades gracefully rather than erroring — individual source failures appear inside `sources[].success: false` with an `error` field, while the overall response remains `200 OK` with `success: true`, except for genuinely unsupported query types.
